# 视频制作

用于做视频；观看开发视频并提炼方法时使用已有研究流程或 gamecraft-research。

## 选择实际可用的路线

- **实机录制**：展示运行中的游戏，适合证明玩法和操作。
- **AI 辅助动效**：用代码/剪辑工具合成图像、流程、配音和字幕，适合介绍技能或讲解机制。
- **模型生成镜头**：核验图像/视频生成能力和素材条件后制作短镜头，再剪辑组装。

结合任务和现有工具决定，可混用并逐镜头标注。实际游戏、概念插画与模型生成片段应清楚区分。没有视频模型时，合适的讲解任务可以完成动效片；不要把它称为已完成文生视频，也不要擅自把用户明确要求的文生视频改成另一种交付。

若用户明确要求真实玩法而游戏不可运行，当前可交付的是分镜、待录镜头表与可重建工程。概念片属于不同的交付路线，须用户明确选择后才制作；素材缺口或等待超时都不构成替代授权。

## 制作

1. 先读现有工程和素材，确定目的、观众、比例、时长、语言和简短分镜。资料已有答案就不重复提问；其余常规选择给默认值。问题只针对无法替代的实机素材或授权缺口，不把可默认的尺寸、时长、语言再列成一串问卷；等待关键答案时继续准备独立可做的分镜和工程。
2. 每个镜头记录主题、动作、镜头运动、视觉路线、素材来源、声音与时间范围。为反复出现的角色锁定参考图、色板和造型。
3. 生成镜头先做短样，检查身份和动作，再扩展；每镜头只安排清楚的主体、动作与相机。字幕、精确 UI 和标题在后期合成。
4. 优先复用已有 Canvas/FFmpeg、Remotion 或剪辑工程。按时间/帧驱动动效，固定随机种子；记录分镜、旁白、资产路径和输出参数。
5. 配音采用已授权录音或合成声音；不默认克隆某个人。旁白前景清晰、背景音乐适当降低，字幕使用高对比和安全边距。
6. 根据当前官方资料核对模型限制和服务费用。只在任务授权内调用服务、安装或发布。

详细渲染与验收见 [制作参考](references/production.md)，选渲染器时再读 [工具路线](references/engines.md)。

## 交付门槛

- 检查实际时长、分辨率、帧率和非静音音轨；全片解码通过。
- 查看每个镜头的开始、中段、结束和字幕；动态问题看连续播放，截图不替代动作检查。
- 旁白与字幕对齐，结尾信息留够阅读时间；记录不能核验的音画问题。
- 保留项目源码、分镜和素材声明，输出可播放文件。
- 使用第三方视频作研究时只发布原创提炼和原链接，不镜像完整音画。

复述本次实际使用的制作路线及验证范围。AI 生成概念镜头不作为游戏交付或性能的证明。
