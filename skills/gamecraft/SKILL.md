# GameCraft：AI 辅助游戏开发执行

本技能管“怎么把游戏做出来并跑起来”。研究与视频制作分别交给 gamecraft-research 和 gamecraft-video；本技能单独可用。

## 何时加载参考

- 做 3D 资产、角色、动画、场景、玩法实现时：读 `references/production.md`。
- 选引擎、查版本差异、评估 MCP/插件/模板来源时：读 `references/engines.md`。
- 只做一个 2D 小玩法或纯代码任务时，两份参考都可跳过。

## 工作原则

1. 沿用用户的引擎、维度和美术方向。没有约束时按目标平台选择能快速跑通的小样，并简述默认值；不按单个演示决定引擎优劣。
2. 对缺少的信息先查项目和已有资料；只有真正影响分支且无法推断的关键偏好才询问，其余自主推进。
3. 一次只实现一个玩法契约。把“能跑、能看到、能操作、有通过/失败”当作一个契约，做完验收再开下一个。
4. 每次验收都要真运行：实际启动构建，注入输入，截图，读日志。不要凭代码阅读宣布成功。
5. 每个可运行阶段设检查点（Git 提交或等价快照）。反复修不动时保留当前改动，比较最近可用状态，重新定位根因；回退不覆盖用户工作。
6. 区分证据类型：视频说法、作者演示、本机测试、已发布游戏，分别标注。对外表述不得混用。

## 执行流程

### 1. 盘点与调研（先于搭建）

- 查本地已有内容：已有工程、模板、可复用脚本、资产、笔记、之前的失败记录。先复用再新建。
- 查官方文档、GitHub 仓库、引擎源码与模板说明。记录来源、版本、日期。版本事实写成“某日来源快照”，不当作实时最新。
- 需要外部检索与取证时，可交接给 gamecraft-research；本技能自己不做无来源断言。
- 产出简短开工记录：目标、平台、选定引擎与理由、模板来源、未决问题。不写长篇问卷。

### 2. 从模板起步

- 新项目先评估引擎模板或可信社区模板；已有工程沿用其结构。模板不适合核心玩法时可自建最小工程。
- 记录模板版本与来源；付费模板按用户授权和实际许可处理。
- 模板跑通并截图确认后，才在其上改玩法。

### 3. 锁定资产规格（身份/单位/轴向/骨架/动画事件）

在导入或生成资产前，先写一页规格并逐项核对：

- 身份：命名规则、唯一 ID、资产来源与许可证。
- 单位：米或厘米、缩放系数、导出比例。
- 轴向：前进轴、上轴、导出/导入时的轴转换。
- 骨架：骨骼命名、根骨骼、绑定方式（人形/通用）、最大骨骼数。
- 动画事件：动作名、循环方式、事件/通知名、帧率与时间基准。

规格不一致时先统一，不带着错误缩放或轴向继续做玩法。

### 4. 可复用角色试玩场

- 做一个独立的试玩场景：可快速切换角色、预览待机/移动/受击动作、显示单位与碰撞体。
- 新角色、新动画先进试玩场验证，再接入正式关卡。
- 这场景是长期资产，后续项目可复用。

### 5. 一次一个玩法契约

对每个契约写：输入、状态变化、可观察结果、失败条件、验收方式（截图/日志/回放）。

- 先做输入与移动，再做关卡元素，最后做结算。
- 代码、编辑器/场景布局、游戏运行分开验收。
- 问题先复现再修：截图、日志、逐项关闭效果定位，不用“再真实一点”这类模糊指令。

### 6. 运行与验收

- 启动实际构建或编辑器 PIE，注入输入，收截图与日志。
- 保存验收证据：截图、关键日志行、构建号、提交哈希。
- 已知问题写进待办，不隐藏；不把“演示看起来不错”当作验收通过。

### 7. 检查点与回滚

- 每次验收通过后提交检查点。
- 回滚前记录当前状态；回滚后重跑同一验收。
- 不覆盖用户已有提交历史或尚未保存的改动。

### 8. 交付

- 交付可运行构建或可运行工程 + 启动说明。
- 附：已验证范围、未验证范围、已知缺陷、来源与版本快照、下一步建议。
- 不做完整引擎升级，除非用户明确要求并单独评估。
- 不宣称保证质量、节省比例或某引擎/模型普遍更优。

## 禁止事项

- 编造 API、命令、端口或版本行为。
- 绑定私有机器路径、强制某云服务或模型供应商。
- 把 UE5.7 教程步骤直接套到 UE5.8；Epic UE5.8 原生 MCP 属 Experimental，按其文档与实测处理。
- 安装、付费与发布沿用本次任务已有授权；缺少授权的外部操作留到具体结果可审阅时处理。

## 与其他技能的分工

- 需要 DeepSeek Search/Fetch 检索与证据整理：交给 gamecraft-research，本技能只消费其结论。
- 需要宣传片/讲解视频：交给 gamecraft-video。
- 两者缺席时，本技能用本地资料与官方文档即可独立完成开发验收。
